1. Explica dos diferencias entre una API REST y un servidor GraphQL. (2 pts)

Respuesta:
Una diferencia es que en REST tienes varios endpoints, uno por cada recurso (como /laptops o /laptops/1) y usas GET, POST, PUT y DELETE, mientras que en GraphQL normalmente solo hay un endpoint y lo que cambia es la query que mandas.

Otra diferencia es que en REST el servidor decide que datos te regresa, entonces a veces te llegan datos que no ocupas o tienes que hacer varias peticiones. En GraphQL el cliente pide solo los campos que necesita y eso es lo que le regresa.


2. Indica una situación en la que conviene usar REST y otra en la que conviene usar GraphQL. (2 pts)

Respuesta:
REST conviene en algo sencillo como un CRUD, por ejemplo el de las laptops, donde solo se agregan, consultan, editan y eliminan registros. Es mas facil de hacer y de probar.

GraphQL conviene cuando hay muchos datos relacionados y diferentes pantallas o apps que necesitan cosas distintas, por ejemplo una red social donde en una sola consulta quieres el usuario, sus publicaciones y los comentarios, sin hacer muchas peticiones.


3. ¿Qué diferencia hay entre una imagen y un contenedor? ¿Qué papel cumple el Dockerfile en esa relación? (2 pts)

Respuesta:
La imagen es como una plantilla que ya trae todo lo que necesita la aplicación (dependencias, codigo, configuracion) pero no se esta ejecutando. El contenedor es la imagen ya corriendo, y de una misma imagen puedes crear varios contenedores.

El Dockerfile es donde se escriben las instrucciones para crear la imagen (FROM, COPY, RUN, CMD, etc). Primero se hace el Dockerfile, con docker build se crea la imagen y con docker run se crea el contenedor.


4. ¿Para qué sirve Docker Compose? En el mapeo 8000:8000, ¿qué representa el primer 8000 y qué representa el segundo? (2 pts)

Respuesta:
Docker Compose sirve para levantar varios contenedores al mismo tiempo usando un archivo docker-compose.yml, por ejemplo la API y la base de datos de MySQL, y ahi mismo se configuran los puertos, variables de entorno y volumenes. Con docker compose up se levanta todo.

El primer 8000 es el puerto de mi computadora (el host), que es el que uso para entrar con localhost:8000. El segundo 8000 es el puerto dentro del contenedor donde esta corriendo la aplicacion.


5. ¿Por qué las laptops del ejercicio 1 se guardan en MySQL y no en una lista de Python? ¿Qué identifica la llave primaria id? (2 pts)

Respuesta:
Porque si se guardan en una lista de Python los datos solo estan en memoria, y cuando se reinicia el programa o el contenedor se pierden. En MySQL los datos se quedan guardados aunque se apague, y ademas se pueden hacer consultas y acceder desde otros servicios.

La llave primaria id identifica a cada laptop de forma unica, no se puede repetir y sirve para buscar, editar o borrar una laptop en especifico.
